# SkillShare discovery (`/skillshare`)

- `SkillShareDiscovery.tsx` orchestrates UI state only; `discoverySource.ts` owns all API I/O and query serialization. It uses the existing Auth0-backed `apiRequest`; no parallel auth or presentation-layer fetch.
- The existing `SwipeLauncher`/`SwipeDeck` remain the only deck and swipe matching flow. `skillOnly` narrows the crossed-card entry to SkillShare; `onDismiss` is optional, local-to-view, reversible and never changes auth, saved searches, swipes or data. Filters must survive dismissal. Escape dismisses only when focus is inside the section and no native dialog is open.
- Filter options are existing server data via `/skillshare/catalog`; category constants mirror server vocabulary mapping, not fake people or credentials. Degrees and ages are not provided/consented public profile fields, so no filters exist yet. Owner follow-up: define consented public fields and server schema before adding them. Year, private location, precise schedules and email remain out of discovery results.
- Match scheduling is enabled only from `/swipe/matches?kind=skill` reciprocal matches. The exchanges list contains actual server lesson records (never placeholder negative IDs).
- Completion requires both participants after the scheduled lesson. Only then can the author add/edit their three 1–5 category ratings via a native dialog. Reload submitted values from exchange `review.values`; these values are private to that participant. Never expose them publicly. `average: null` + `completed_reviews: 0` means “No ratings yet,” never zero reputation.
- Preserve native dialogs, accessible radio groups, visible focus, reduced motion, no horizontal overflow at 390px, and the shared dashboard header/typography. Register the shared dashboard stylesheet to preserve the floating header's exact dimensions.
- Verification: `npm run type-check`, lint/build, `discoverySource.test.ts` with Vitest, and `playwright test --config tests/dashboard-playwright.config.ts tests/skillshare-discovery.spec.ts`. Mock only protected test identity/API at the harness boundary, never Auth0 verification in app code.
