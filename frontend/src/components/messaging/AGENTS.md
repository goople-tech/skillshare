# Shared private messaging

- `MessagingPage` is the sole inbox/conversation implementation. Thin routes at `/buddies/messages` and `/skillshare/messages` pass different `kind` values; query `?conversation=<id>` selects a thread. Do not fork this state/UI by route.
- `messagingSource.ts` maps the Auth0-backed `apiRequest` adapter to FastAPI `/conversations` and `/:id/messages`, `/:id/read`. Bearer identity, safe participant fields and durable numeric IDs come from the server. No DeepSpace records, preview identities or sample messages are production sources.
- A mailbox is only usable while both reciprocal same-kind swipe likes exist. The server rechecks membership and authorization on every read/write/read-cursor operation; the URL is never authorization. SkillShare lessons/ratings are not message eligibility.
- Manual Refresh requests list/history anew. Merge message pages by server ID with `mergeMessages`; historical pages use exclusive `before` IDs. No fabricated delivery, online status, read receipt, match or message state.
- Compose is awaited, so failure preserves the draft and never inserts a success bubble. The send button disables only during the actual request. Cmd/Ctrl+Enter submits. On mobile, thread selection replaces the list and Back uses a navigable route action.
- Unread badges come from the server. Reading is not assumed on open; a separate explicit POST confirms only the current participant's cursor. No receipts for the other person. Draft focus and hidden documents defer automatic read confirmation.
- Preserve accessible sender labels, role=group history, visible focus, text escaping (never `dangerouslySetInnerHTML`), loading/error/empty states, 2,000-character bounds and no-horizontal-overflow mobile layouts.
- Component/browser tests may use purpose-built API fixtures, but those fixtures must stay in `src/components/messaging/*.test.ts`, `frontend/tests/messaging*`, or test-only Vite aliases. `MessagingPage.test.tsx` explicitly uses the Happy DOM annotation because the default vitest environment is Node while `render`, `window.matchMedia`, and `document.hidden` need browser primitives. Don't remove its environment annotation when renaming or adding this test tree to the shared runner; the dedicated `vitest.messaging.config.ts` also uses Happy DOM.
- Thin page wrappers mount the existing Auth0 `SessionProvider`; browser HTTP fixtures substitute responses, not server verification. One `Messages` link enters the shared workspace; buddy/skill links within it remain context-scoped.
- Confirmed mutual matches resolve through the same server list: `?participant=<id>` from swipe match cards requires a partner-and-kind match from `/conversations`; it is not a conversation ID. Deck matches use `ApiSwipeSource.resolveConversation` then navigate to the returned numeric ID. Never infer partner==conversation IDs or sample-match success; a lookup failure leaves an actionable error, never a success.
