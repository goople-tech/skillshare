# Swipe decks (Buddies / SkillShare)

- `SwipeLauncher` is mounted in `DashboardView` as the Speed Matching section (`#meet`): crossed phone cards (`CrossedCards`) beside `MatchBrowser` (six filter chips + match tiles for the selected deck), the full-screen deck (`SwipeDeck`, native `<dialog>`), and a strip of mutual matches.
- The nav's Buddies tab goes to `/home#buddies`; the hash (`#buddies` / `#skillshare`) selects which phone is in front, and switching phones updates it. The SkillShare tab keeps its own `/skillshare` page, which reuses the launcher with `skillOnly` (single phone, no `MatchBrowser`; that page has its own discovery grid).
- Each phone selection shows a random prompt from `QUIRKS` (never the same one twice in a row) plus "Select ←/→". The selected deck's arrow or phone opens the deck; the other arrow or phone switches decks. Keys act only while the section is ≥45% visible or fills ≥40% of the screen (zoomed-in pages) and no dialog is open.
- `filters.ts` defines the filters (AND-combined, keeping the server's order, built only from server fields and reasons). Tile Like/Pass records the same swipe as the deck and removes the tile only after the server acknowledges it; a match offers a link to the existing messages page.
- In a deck, the first ←/→ tilts the top card (PASS/LIKE preview), the same key again commits, the opposite key switches, ↓/Backspace or Esc cancels (Esc again closes). Cards can also be dragged (110px or a fast flick) or swiped with the round buttons.
- Data goes through `swipeSource.ts` only (`ApiSwipeSource` → FastAPI `/swipe/{buddy|skill}/deck`, `POST /swipe`, `/swipe/matches`). `cardFromApi` is the single mapping point. Components never fetch.
- Ordering is compatibility only (shared courses/interests/skills, meeting mode, pace). No popularity/Elo rating and no numeric score is sent or shown; cards show plain-language reasons from the server.
- Swipes are optimistic with rollback: the card leaves immediately, and returns on a failed request with a visible message. Matches are shown only after the server reports `matched: true`.
- `PreviewSwipeSource` is a labelled, in-memory sample deck offered only when the service can't be reached. It never reports matches and saves nothing.
- `SwipeLauncher skillOnly` and `CrossedCards` scope props allow `/skillshare` to reuse this same matching/deck code without duplicating it. Optional `onDismiss` makes its wrapper an in-memory, reversible optional section; dismiss must not erase filters, swipes or identity. Focused Escape only acts outside dialogs. The launcher has the 44px dismiss control; the deck retains its own native-modal close/Escape behavior.
- Respect `prefers-reduced-motion`; keep 390px with no horizontal overflow. Unit tests: `swipeSource.test.ts`, `filters.test.ts`, `quirks.test.ts`.
- Mutual API matches can use `resolveConversation(deck, partnerId)` to require a partner-and-kind match from authorized `/conversations` then navigate to its server ID, without creating a client match or posting messages. `MessagingPage` resolves the same partner link for saved match cards. Preview sources intentionally have no such message integration.
